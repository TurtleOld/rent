# Одна квитанция на содержимое PDF

Повторная загрузка того же PDF одним пользователем возвращает уже существующую квитанцию. Совпадение определяется SHA-256 содержимого файла, а не именем: имя меняется при скачивании и копировании, содержимое — нет. Уникальный индекс `(user, content_hash)` держит правило в базе, поэтому одновременные запросы не создают две записи. Проигравшая гонка удаляет свой лишний файл и получает существующую квитанцию.

Одинаковый PDF у разных пользователей — разные квитанции: чужие данные не раскрываются и не смешиваются. После удаления квитанции её содержимое можно загрузить снова. Неудачный разбор не блокирует повторную загрузку: возвращается существующая квитанция, и пользователь запускает повторный разбор.

## Существующие данные

Миграция проставляет хэш первой по времени копии содержимого у каждого пользователя. Более поздние исторические дубли остаются с пустым хэшем: уникальный индекс не сравнивает `NULL`, поэтому записи и файлы не удаляются молча. Новые загрузки такого содержимого возвращают первую копию. Старые дубли по-прежнему видны в итогах и графиках; их разбор — отдельная задача.

## Рассмотренные варианты

- **Сравнивать имя файла.** Не работает: одно и то же содержимое приходит под разными именами.
- **Проверять только в приложении.** Два одновременных запроса проходят проверку до вставки и создают дубли.
- **Удалить исторические дубли миграцией.** Молча меняет итоги и уничтожает файлы, которые пользователь не просил удалять.
